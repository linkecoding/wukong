# SDK 首轮回归：保留失败结果

实测版本 `01c3b86`，完整跑完 12 次，9 次成功。此轮不能作为性能提升的成功结论；所有记录均保留，后续完整复测单独存放。

- 3 次任务因严格条件解析直接终止：第二组的 retry/JS、retry/工具、batch/工具。模型生成 selector-only 条件简写时，新增解析器抛出了异常；异常发生在模型决策阶段，没有进入原有动作校验反馈路径。
- retry/JS 的页面 oracle 已通过，但 finish evidence 采用简写，最终引擎仍 FAILED。这种情况仍算失败。它的摘要还错误声称没有重试，而真实请求包含一次重试；不能只凭摘要判断执行正确。
- batch/JS 的一次局部失败来自 Object.assign 修改不可变选择器。此前已经接受的操作没有回滚，恢复时未重复成功查询。
- 另一次 JS 错误来自 timeoutMs=15000，超出既有条件等待上限；结构化错误保留了先前两次已接受操作，模型继续读取当前状态。

修复方向是明确规范化无歧义简写、把其余参数错误作为有上限的本地校验反馈，补充不可变选择器与等待范围说明。未放开未知字段，也未自动重试已发出的设备操作。

额外离线测试发现空输入的 getText 可能返回提示文字，最终实现使用 isShowingHintText 区分实际空值。清空与状态不变时的 no-op 都经过真实 shell 验证。
